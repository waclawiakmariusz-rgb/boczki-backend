# Estelio — stały standard przekazywania redesignu

Ustalenie użytkownika z 22.10.2026. Stosować przy kolejnych redesignach Estelio, o ile użytkownik nie wskaże inaczej.

Każdy redesign kończ gotową paczką ZIP do pobrania, bez czekania na dodatkową prośbę o spakowanie.

Paczka powinna zawierać:

1. Finalną makietę lub makiety graficzne w stylu „lekki nowy” („nowy lekki”), dotyczące zamówionego zakresu.
2. Szczegółowy plik Markdown z instrukcją dla Claude Code: zakres zmian, układ, typografia, kolory, odstępy, zachowania, responsywność, stany błędu/puste/ładowania oraz kryteria odbioru.
3. Krótki plik START wskazujący kolejność czytania i główny dokument.
4. Kod HTML/CSS/JS i inne materiały tylko wtedy, gdy zostały zamówione lub zaakceptowane jako zakres. Makieta i instrukcja nie oznaczają automatycznej zgody na wdrożenie na produkcję.

Nie przenoś zmian na pozostałe moduły, menu ani procesy biznesowe bez uzasadnienia w zleceniu. Wskaż wyraźnie, które elementy grafiki są wyłącznie kontekstem lub przykładami danych. Nie przedstawiaj niezweryfikowanych założeń jako faktów o aktualnym kodzie.

Przed przekazaniem sprawdź kompletność ZIP-a i zgodność nazw plików z odwołaniami w instrukcji. Zapisz gotową paczkę trwale, a w końcowej odpowiedzi podaj bezpośredni link do pobrania. Nie kończ pracy samą wyświetloną grafiką ani zapowiedzią późniejszego pliku MD.

Nazewnictwo: Estelio_[Modul]_Lekki_Nowy_RRRR-MM-DD.zip. Numer wersji dodawaj przy kolejnych korektach tego samego dnia.

Ten dokument jest zapisem preferencji projektowej, nie instalowalnym skillem i nie zmianą kodu Estelio. Dołączaj go do paczek przekazywanych wykonawcy.
